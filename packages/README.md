# Generated clients

Everything under `packages/` is generated by `scripts/gen.sh` from `specs/*.yaml`.
Do not edit these files by hand: change the spec, then regenerate.

| Path | Source | Package / crate |
| --- | --- | --- |
| `packages/python/shiprocket` | `specs/shiprocket.yaml` | `open-logistics-shiprocket` (`open_logistics_shiprocket`) |
| `packages/python/delhivery` | `specs/delhivery.yaml` | `open-logistics-delhivery` (`open_logistics_delhivery`) |
| `packages/rust/open-logistics` | `specs/*.yaml` | `open-logistics` (`open_logistics`) |

## Method names

Method names come from `operationId`, so they match across the generated
languages:

| TypeScript | Python | Rust |
| --- | --- | --- |
| `client.orders.create(...)` | `OrdersApi.orders_create(...)` | `orders_api::orders_create(...)` |
| `client.orders.list(...)` | `OrdersApi.orders_list(...)` | `orders_api::orders_list(...)` |
| `client.tracking.byAWB(...)` | `TrackingApi.tracking_by_awb(...)` | `tracking_api::tracking_by_awb(...)` |

## Python

```bash
pip install ./packages/python/shiprocket ./packages/python/delhivery
```

```python
from open_logistics_shiprocket import ApiClient, Configuration, OrdersApi

configuration = Configuration(host="https://apiv2.shiprocket.in/v1/external")
with ApiClient(configuration) as api_client:
    auth = AuthApi(api_client).auth_login(AuthCredentials(email=..., password=...))
    configuration.access_token = auth.token
    order = OrdersApi(api_client).orders_create(payload)
```

Delhivery uses `api_key={"delhiveryToken": token}` plus
`api_key_prefix={"delhiveryToken": "Token"}`.

## Rust

```toml
[dependencies]
open-logistics = { path = "packages/rust/open-logistics" }
```

```rust
let mut configuration = open_logistics::shiprocket::apis::configuration::Configuration::new();
let auth = open_logistics::shiprocket::apis::auth_api::auth_login(
    &configuration,
    AuthCredentials { email, password },
).await?;
configuration.bearer_access_token = Some(auth.token);
let order = open_logistics::shiprocket::apis::orders_api::orders_create(
    &configuration,
    payload,
).await?;
```

Delhivery sets `configuration.api_key = Some(ApiKey { prefix: Some("Token".into()), key: token })`.

## Delhivery returns raw provider payloads

Unlike the TypeScript `DelhiveryClient`, the generated clients do not normalize
responses. `DelhiveryTrackingResponse` exposes `ShipmentData`; `rates_calculate`
returns the provider's array of charge estimates (`total_amount`,
`gross_amount`, `tax_data`); packing slips expose `pdf_url` and
`packages_found`; waybill fetches return the waybill number string. Process
these payloads yourself if you need the same convenience fields the TypeScript
SDK computes.

The generated clients also do not inject credentials into query parameters.
The TypeScript waybill helpers send `cl`, `client_name`, and `token` as query
parameters; pass them explicitly if your Delhivery account requires them.

## One operation per path + method

OpenAPI cannot describe two operations on the same path + method, so
TypeScript convenience aliases collapse:

- Shiprocket `checkServiceability` and `calculateRates` both map to
  `courier_serviceability`.
- Delhivery `createOrder`/`updateOrder`/`cancelOrder` map to `orders_create`
  and `orders_edit`.
- Delhivery `trackByWaybill`/`trackByOrderId`/`trackByWaybills` map to
  `tracking_fetch` with different query parameters.
